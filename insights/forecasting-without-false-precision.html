Forecasting without false precision

A model can calculate twelve decimal places from assumptions that are barely known. Honest forecasting keeps those two facts separate.

Forecasting often fails at the interface between mathematics and language. A deterministic calculation is reported as if it were a probability. An assumption becomes a fact after being repeated. A scenario boundary disappears from the executive summary.

Translate the question before calculating

“Will this market grow?” is not a model input. Define the variable, geography, horizon, baseline date and decision threshold. If the answer is supposed to trigger an action, write that action down. Different decisions may need different forecasts even when they concern the same topic.

Separate three layers

  • Calculations: results that follow mechanically from stated inputs and formulas.
  • Assumptions: choices about future rates, causal relationships or missing data.
  • Uncertainty: the range of outcomes compatible with plausible inputs and model limits.

Never hide an assumption inside a calculation table. If an input is a judgment, label it as a judgment and show how the output changes when it moves.

Use more than one method only when methods disagree usefully

Running many models is not automatically rigorous. Methods that share the same data and assumptions can repeat the same error. A useful ensemble contains approaches with meaningfully different failure modes: a baseline trend, a structural model, a scenario tree and an outside-view reference class.

Make sensitivity visible

A forecast is operationally weak when a small, plausible change in one input reverses the decision. Rank inputs by their effect on the outcome. Show break-even values: the precise point at which the recommendation changes. This turns uncertainty into a plan for collecting better information.

Good output: “The decision is robust across the tested range except when input X exceeds Y.” Bad output: “Our AI predicts a 73.4% chance” without a calibrated history.

Do not confuse scenario probability with model confidence

A scenario may be assigned a probability, while confidence in the entire modeling process is a different question. Confidence depends on data quality, structural adequacy, calibration and whether the event resembles the model's past domain.

Write the disconfirmation condition

Every forecast should state which incoming observation would make it obsolete. Add a review date and an owner. Forecasts should expire; otherwise they remain on slides long after the world has changed.

One-page forecast
  • decision and horizon;
  • source data and cutoff date;
  • calculations separated from assumptions;
  • sensitivity and break-even values;
  • uncertainty range and known blind spots;
  • update trigger and falsifier.

The purpose is not to make uncertainty disappear. It is to prevent uncertainty from being mistaken for certainty at the moment a decision is made.
